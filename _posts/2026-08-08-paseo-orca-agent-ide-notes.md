## 한 줄 요약
**Paseo와 Orca는 둘 다 여러 AI 코딩 에이전트를 실제 프로젝트 안에서 돌리고 관리하는 도구이지만, Paseo는 “내가 이미 쓰는 에이전트를 여러 기기에서 편하게 다루는 인터페이스” 쪽이 강하고, Orca는 “여러 에이전트를 병렬 워크트리와 리뷰 흐름으로 굴리는 오케스트레이션 작업실” 쪽 색이 더 강해 보였습니다.**

## 왜 이 글을 남기나
공유해 주신 원문은 Paseo를 빠르게 소개하면서 이런 포인트를 강조합니다.

- GUI가 있다
- 시스템 프롬프트를 관리할 수 있다
- VPN 없이 원격 접속할 수 있다
- 모바일/웹으로 이어서 쓸 수 있다
- Orca와 비교했을 때 입문자 친화적이다

짧게 읽기에는 좋지만, 나중에 다시 볼 때는 몇 가지가 헷갈릴 수 있습니다.

- Paseo가 정확히 무엇인지
- 단순 AI IDE인지, 에이전트 실행기인지
- Orca와 차이가 정말 인터페이스 정도인지
- 원격 접속과 모바일 지원이 어느 정도까지 되는지

그래서 원문을 출발점으로 삼되, **Paseo 공식 사이트와 Orca 공개 README 기준으로 무엇이 확인되는지** 공부용으로 다시 정리해 둡니다.

## 원문에서 말한 핵심
원문 블로그 글을 차분하게 풀면 핵심은 대략 이렇습니다.

1. **Paseo는 GUI와 원격 접속을 갖춘 AI 터미널/IDE다.**
2. **시스템 프롬프트를 프로젝트 성격에 맞게 관리할 수 있다.**
3. **웹/모바일로 원격 작업을 이어 갈 수 있다.**
4. **Orca보다 더 가볍고 직관적인 선택지로 볼 수 있다.**

방향성 자체는 꽤 이해가 됩니다. 다만 공식 자료까지 같이 보면, 이 둘의 차이는 단순히 “GUI 있냐 없냐”보다 **무엇을 더 중심 가치로 두는가**에서 갈리는 것처럼 보였습니다.

## 공식 자료로 다시 확인한 것

### 1. Paseo는 “에이전트를 직접 돌리는 작업실”이라기보다 “기존 에이전트를 묶어 주는 인터페이스”에 가깝다
Paseo 공식 사이트 첫 문장은 성격을 꽤 분명하게 보여 줍니다.

> Run any coding agent from your phone, desktop, or terminal.

즉 Paseo의 핵심은 새로운 자체 모델을 파는 것이 아니라,

- Claude Code
- Codex
- OpenCode
- Pi
- Cursor 등

**이미 존재하는 에이전트/CLI를 한 인터페이스에서 다루게 해 주는 것**에 있습니다.

공식 FAQ에도 비슷한 취지의 설명이 나옵니다.

- Paseo는 각 provider의 native harness를 사용한다
- 기존 구독, 스킬, 설정, MCP 서버가 계속 동작한다
- 코드 자체를 Paseo가 따로 가져가서 처리하지 않는다

즉 이 도구를 한 문장으로 줄이면,

> **“내가 이미 쓰던 AI 코딩 도구들을, 데스크톱·웹·모바일·CLI 사이에서 이어서 관리하게 해 주는 레이어”**

라고 이해하는 편이 가장 덜 과장됩니다.

### 2. Paseo의 강점은 “기기 이동”과 “접속 편의성” 쪽에 분명히 있다
원문이 강조한 “원격 접속” 포인트는 공식 사이트와도 잘 맞습니다.

Paseo는 공식적으로 다음을 말합니다.

- 데스크톱, 웹, 모바일, CLI 지원
- 랩톱, VM, 개발 서버 위에서 에이전트 실행 가능
- 직접 연결 또는 종단간 암호화 relay 사용 가능
- 외부 네트워크에서는 hosted relay, 자체 tunnel, 직접 포트 노출 등 여러 방식 가능

이 말은 곧,

- 책상 앞이 아니어도 상태를 볼 수 있고
- 휴대폰에서 진행 상황을 확인하거나 후속 지시를 보낼 수 있으며
- 굳이 복잡한 개인 VPN 구성을 먼저 하지 않아도 시작 가능한 길이 열려 있다는 뜻입니다.

그래서 원문의 “VPN 없는 원격 코딩” 요지는 과장만은 아닙니다. 정확히 말하면 **원격 자체가 마법처럼 자동이라는 뜻이 아니라, 기본 relay와 여러 연결 옵션 덕분에 진입장벽이 낮아졌다**는 쪽이 더 맞아 보입니다.

### 3. Paseo는 worktree도 지원하지만, 핵심 인상은 “가벼운 접속성 + 여러 기기 연속성”이다
Paseo 공식 FAQ를 보면 Git worktree도 분명히 지원합니다.

- worktree 옵션으로 에이전트를 띄우면
- Paseo가 git worktree를 만들고
- 분리된 브랜치에서 에이전트를 돌린다

즉 “GUI만 있고 Git 격리는 약하다”는 식으로 이해하면 틀립니다. 다만 공식 사이트의 전체 메시지를 보면 첫 인상은 조금 다릅니다.

Paseo가 전면에 내세우는 것은 주로 이런 것들입니다.

- 어느 기기에서든 에이전트에 접속 가능
- 기존 provider CLI를 그대로 활용
- 웹/모바일과 연결
- 빠른 실행과 follow-up
- optional relay/hub

그래서 저는 Paseo를 **“에이전트 실행 환경의 접근성을 크게 높여 주는 정리된 프런트엔드”** 쪽으로 이해하게 됐습니다.

### 4. Orca는 공식 자료 기준으로 훨씬 강하게 “병렬 에이전트 운영실” 이미지를 밀고 있다
Orca 공개 README의 핵심 문장은 이렇습니다.

> The AI Orchestrator for 100x builders.

또 설명에는 이렇게 적혀 있습니다.

> Run Codex, ClaudeCode, OpenCode or Pi side-by-side — each in its own worktree, tracked in one place.

즉 Orca의 중심 이미지는 명확합니다.

- 여러 에이전트를 동시에 돌리고
- 각 에이전트를 별도 worktree에 분리하고
- 결과를 비교하고
- 검토/주석/커밋/PR 흐름으로 이어 가는 것

공개 README에서 눈에 띄는 기능만 봐도 이 성격이 드러납니다.

- **Parallel Worktrees**: 하나의 프롬프트를 여러 에이전트에 병렬로 보내고 결과 비교
- **Annotate AI Diffs**: diff 줄 단위로 코멘트를 남겨 다시 에이전트로 보내기
- **GitHub & Linear, Native**: 이슈/PR/프로젝트 보드와 직접 연결
- **SSH Worktrees**: 원격 머신에서 에이전트 실행
- **Design Mode**: 실제 브라우저 UI 요소를 클릭해 에이전트 프롬프트에 연결
- **Computer Use**: 화면 상호작용이 필요한 작업 지원

즉 Orca는 단순히 “예쁜 GUI가 있는 터미널”보다,
**에이전트 여러 명을 병렬로 굴리고, 비교하고, 리뷰하고, 합치는 운영 환경** 쪽에 훨씬 가깝습니다.

### 5. 그래서 원문의 “Paseo vs Orca” 비교는 방향은 맞지만, 조금 단순화되어 있다
원문은 대체로 이런 구도로 정리합니다.

- Paseo: GUI, 쉬운 원격 접속, 입문자 친화적
- Orca: 깊은 Git/GitHub/Jira 협업, 헤비 유저 지향

이 구분은 **완전히 틀렸다고 보긴 어렵습니다.** 실제로 Paseo 공식 사이트는 접속 편의성과 다기기 연속성을 강하게 강조하고, Orca 공식 README는 병렬 워크트리와 리뷰 흐름을 매우 강하게 강조하니까요.

하지만 그대로 외워 두면 오해가 생길 수 있습니다.

예를 들어,

- Orca도 모바일 컴패니언이 있고
- Orca도 원격 머신에서 에이전트를 돌릴 수 있으며
- Paseo도 worktree와 CLI 자동화를 지원합니다.

즉 차이는 “이 기능이 있냐 없냐”보다,

- **Paseo는 여러 기기에서 기존 에이전트를 자연스럽게 다루는 경험**
- **Orca는 여러 에이전트를 병렬 워크플로와 리뷰 구조로 조직하는 경험**

중 어디에 더 무게를 두느냐로 보는 편이 더 정확해 보입니다.

## 내가 이해한 가장 쉬운 구분

### Paseo를 이렇게 보면 이해가 쉽다
> **내가 이미 쓰는 Claude Code, Codex 같은 도구를 휴대폰/웹/데스크톱 어디서나 이어서 다루게 해 주는 연결 레이어**

잘 맞는 경우:

- 이미 쓰는 에이전트 CLI가 있다
- 사무실/집/외부 이동 중에도 상태를 보고 싶다
- 원격 접속 세팅을 너무 무겁게 하고 싶지 않다
- 한 사람이 여러 기기에서 개인 생산성을 높이고 싶다

### Orca를 이렇게 보면 이해가 쉽다
> **여러 에이전트를 worktree 단위로 병렬 운영하고 비교·리뷰·병합까지 이어 가는 오케스트레이션 작업실**

잘 맞는 경우:

- 같은 작업을 여러 에이전트에게 병렬로 시켜 보고 싶다
- 결과 비교와 diff 리뷰가 중요하다
- GitHub/Linear/PR 흐름과 더 강하게 붙여 쓰고 싶다
- “에이전트 한 명”보다 “에이전트 팀 운영”에 더 관심이 있다

## 둘 다 결국 무엇을 바꾸는가
둘 다 공통적으로 바꾸는 것은 **AI 코딩을 “한 번 질문하고 답 받는 채팅”에서 “실제 작업 흐름”으로 옮긴다**는 점입니다.

예전에는 보통 이랬습니다.

1. IDE에서 작업하다가
2. 터미널이나 웹 채팅창에 프롬프트를 넣고
3. 결과를 복사해 오고
4. Git 작업은 사람이 따로 정리한다

그런데 Paseo나 Orca 같은 도구는 이 과정을 점점 이렇게 바꿉니다.

1. 프로젝트 안에서 에이전트를 실행하고
2. 상태를 계속 추적하고
3. 필요하면 다른 기기에서 이어 보고
4. diff/브랜치/리뷰/후속 지시를 한 흐름 안에서 처리한다

즉 핵심은 “AI가 더 똑똑해졌다”보다,
**AI를 쓰는 작업 환경이 훨씬 더 운영 가능한 형태로 변하고 있다**는 데 있습니다.

## 나중에 다시 볼 때 기억할 포인트
- **Paseo는 기존 에이전트 CLI를 여러 기기에서 자연스럽게 이어 쓰게 해 주는 인터페이스 레이어에 가깝다.**
- **Paseo의 강점은 GUI 자체보다, 웹/모바일/CLI를 묶는 접속성과 연속성에 있다.**
- **Orca는 병렬 worktree, diff 주석, PR 흐름 같은 오케스트레이션 성격이 더 강하다.**
- **둘 다 단순 AI 채팅 앱이 아니라 실제 프로젝트 작업을 관리하는 환경이라는 점이 중요하다.**
- **원문의 비교표는 빠르게 감을 잡기엔 좋지만, 실제 차이는 ‘기능 유무’보다 ‘어떤 작업 경험을 중심에 두는가’로 보는 편이 더 정확하다.**

## 아직 헷갈리는 것
- Paseo의 실제 대규모 협업 경험이 Orca 수준의 리뷰/조직 흐름까지 얼마나 넓게 커질지는 더 지켜봐야 한다.
- Orca의 기능 폭이 넓은 만큼, 초보자가 느끼는 복잡도는 실제 사용 시 어느 정도인지 직접 써 봐야 안다.
- 두 도구 모두 빠르게 변하는 영역이라, 몇 달 뒤에는 기능 차이가 지금보다 줄어들 수 있다.

## 나중에 더 볼 것
- Paseo CLI 문서를 따로 읽고 실제 follow-up 작업 흐름이 얼마나 매끄러운지 보기
- Orca의 worktree 운영 방식과 diff 주석 흐름을 실제 예시로 다시 보기
- “여러 기기에서 이어서 쓰기”와 “병렬 에이전트 비교” 중 내 작업 스타일에 더 중요한 것이 무엇인지 정리해 보기
